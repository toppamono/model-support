# モデル分類型支援

小学校の通級指導教室・巡回指導・学級担任等が、児童一人につき **2つの指導課題** を設定し、次の個別指導を具体的に組み立てるための実務支援ツールです。

このプロジェクトは児童を固定的なタイプに分類することを目的としません。本人・学校・家庭の困り方や場面を整理し、現在の課題状態について仮説を立て、**目標・具体的な手立て・使用教材・評価**までを一続きで検討できることを目指します。

## 現在のプロトタイプ方針

基本の流れは次の通りです。

1. **相談入口**
   - 学年
   - 性別（任意）
   - 診断・特性（任意）
   - 本人・学校・家庭の困り感と具体的な声
2. **2つの課題設定**
   - 現在は12領域・48課題分類を使用
   - 相談内容から候補を提示するが、自動決定はしない
   - 教師が2つの課題を選択・修正する
3. **2本の個別指導プラン**
   - 長期目標案
   - 本人の実態・課題
   - 短期指導目標
   - 具体的な手立て
   - 教材候補
   - 評価の参考例
4. **試行・評価・再検討**
   - 分類、指導案、教材候補の妥当性を実践から見直す

2つの課題は左右に並べ、同じ児童について別々の個別指導計画として比較・編集できることを重視します。

## 今後もっとも検証する部分

### 1. 48課題分類
現在の48分類を完成版とは考えません。

- 現場の困り方を十分に表しているか
- 似すぎている分類は統合すべきか
- 1分類の中に異なる指導課題が混ざっていないか
- 同じケースを見た教師同士で大きく判断がずれないか
- **分類を分けることで実際の指導判断が変わるか**

を検証し、必要なら統合・分割します。

### 2. 指導プラン
分類が合っていても、目標や手立てが不適切なら実務ツールとしては機能しません。

特に、

- 学年
- 具体的な場面
- つまずきの観点
- 必要な人的支援の量
- 本人の認識・希望

を踏まえて、短期目標・手立て・評価が適切に変わるかを検証します。

### 3. 教材候補と優先順位
教材の母体は **Notion「使用教材」** とします。

モデル分類型支援側では、

**見立て → 課題 → 指導プラン → Notion教材から候補抽出 → 仮の優先順位で表示**

を担当します。

教材順位は固定された正解ではなく検証対象です。将来的には、

- 課題との一致
- 学年
- つまずき
- 支援量
- 個別／小集団
- 所要時間
- 文字・言語負荷
- 教材形式
- 過去の実践結果

などを使って順位を改善します。

自治体、研究機関、市販教材等から新しい教材を追加する場合も、原則として内容と利用条件を確認して **Notion「使用教材」へ登録した後** に推薦対象へ加えます。

## 基本原則

- 診断名・障害種だけから課題・教材・支援方法を決めない
- 性別は補助情報として扱い、ステレオタイプによる分岐を行わない
- モデルは「児童そのもの」ではなく「現在の課題状態」を表す
- 本人・学校・家庭の困り感を分けて扱う
- 周囲だけが困っている場合は、本人への訓練だけでなく環境調整も検討する
- 出力は診断ではなく、教師の見立て・試行・再評価を支える下書きとする
- 実在児童の個人情報をGitHubへ保存しない

## 正式な最新版

**GitHub の `main` ブランチを唯一の最新版として扱います。**

ChatGPT、Codex、ローカルPCのいずれで作業する場合も、作業開始前に `main` の最新状態を確認し、変更後はGitHubへ反映します。ローカルPC内だけに存在する変更は正式版とはみなしません。

## 開発の役割分担

- **ChatGPT**：教育的妥当性、分類・教材マッピングの検討、UX、仕様整理、レビュー、小規模修正
- **Codex**：実装、リファクタリング、複数ファイル変更、テスト、ローカル検証
- **Notion「使用教材」**：教材ライブラリの基準データ
- **GitHub**：アプリ本体、分類・推薦ロジック、検証ケース、変更履歴の基準点

## 個人情報

公開リポジトリには、実在する児童名、学校名、保護者情報、相談記録、個別指導計画などを保存しません。テストには架空ケースを使用します。
